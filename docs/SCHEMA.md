# Static data contracts · v2

All dates use UTC and ISO 8601. Longitude precedes latitude in envelopes. The site loads one region at a time.

- `processing_metadata.json` is the companion SI-use disclosure for IGNIS processing software and derived analytical outputs. It identifies ChatGPT/Codex assistance separately from the authentic NASA observations, links to `sources.json`, and does not modify the source records or analytical values. It is a static documentation file, not an input to scientific calculations.
- `sources.json` lists eight source-member records. Integer IDs link samples and daily source counters to ZIP hashes, field names, versions, dates, null counts, confidence values, envelopes and QA ledger. The generated CSV manifest carries the same metadata.
- `{region}/summary.json` contains the observed envelope, first/last detection dates, calibration evidence, daily and monthly arrays and the column names. Each summary row is [period, raw MODIS, raw VIIRS, retained MODIS observations, retained VIIRS observations, MODIS-only cell-days, VIIRS-only cell-days, both-sensor cell-days, archive MODIS rows, archive VIIRS rows]. The last two columns plus raw totals identify NRT contributions. Raw counts precede filtering and deduplication. Retained observations satisfy confidence and identity rules. The union is the sum of the three disjoint cell-day counts. Only dates with source rows are serialized. Clients construct gaps with an explicit coverage state. Monthly counts sum daily observations or cell-days.
- `{region}/maps/YYYY.json` maps months to arrays of point samples. Row fields are [UTC day of month, HHMM string, latitude, longitude, source ID, satellite, confidence, FRP in MW or null, day/night, type or UNKNOWN, version, retained flag]. Deterministic capped samples stratified by day, sensor and confidence-policy result allow drilldown. Client display caps may thin further. Raw files remain the authoritative complete point record.
- `data/work/{region}-cells.csv.gz` is a local, unsampled table of retained date/cell pairs, both grid indices and observation counts by sensor. The parent totals and custom-area queries use identical occupancy semantics.
- `{region}/area/YYYY.bin` is an unsampled, UTC-day-sorted index of every valid input point before deduplication. Each 12-byte little-endian record has int32 longitude and latitude in 1e−7 degrees, uint16 UTC days since 1970-01-01, one flag byte and one classification byte (0 unknown, 1 presumed vegetation, 2 volcano, 3 static land, 4 offshore). Bit 0 is NRT, bit 1 is VIIRS, bit 2 is unique and quality-retained. The build verifies lossless coordinate encoding. A worker lazily caches relevant years, tests all four rectangle edges inclusively, sums raw and archive counters, and unions retained sensor occupancy one UTC day at a time.
- Aggregate CSV exports provide one row per selected day or month. The chosen metric is blank for unsupported periods. Additional fields retain classification, a descriptive reference median and N matched to each row's exact `reference_from_utc` / `reference_to_utc`, historical gap advisories, source counters, overlap components, quality policy, independent measure and sensor, AOI selection method and W/S/E/N coordinates, definition, coverage, partial intervals and comparison eligibility. Month/day drilldown narrows these exports and map panels while the calendar overview retains its selected range.
- Selected hotspot CSVs are unsampled projections of the point indices for up to 31 inclusive UTC days, with region, UTC acquisition date, longitude, latitude, sensor, processing status, source member, original FIRMS type (blank if unknown), inferred class and grid-retention flag. All selected-area/class/sensor/date filters apply. Raw mode includes all valid source rows; grid mode includes only quality-retained unique observations. Rows are not occupied cell-days. Different source observations can have identical projected fields because HHMM, FRP and original confidence are absent; they must not be deduplicated on this reduced schema. Source member links to complete provenance in `sources.json`.
- Calendar SVG exports preserve the full calendar date filter, AOI, classification, sensor, units, recorded monthly totals, unavailable/unknown/partial states and selected-month outline. Its scope can therefore be wider than the drilldown CSVs. It is a standalone vector visualization, not a scientific anomaly map.
- Aggregate CSVs additionally include `reference_policy` (`other` retrospective or `earlier`), exact reference years, eligibility status, Q25/Q75/P10/P90, midrank percentile, signed/relative median deviation, MAD and deviation/MAD. Unsupported values are blank. Reference distributions require five eligible years; deviation/MAD requires eight and positive MAD. `comparable_baseline_n` remains zero because observationally complete anomaly baselines are unavailable. The `recorded_` prefix is intentional.
- Record-support columns count in-range selected sensor-days with records, without records, with NRT and with zero retained counts after quality filtering. They derive from the same selected-area/class source rows. `observation_completeness` remains `UNKNOWN`; these counters are not clear-sky fractions or imputations.
- `transfer-validation.json` is a derived diagnostic, never a runtime calibration lookup. It contains separately labeled occupancy and retained-detection targets, pooled/seasonal factors and training support, temporal/spatial/season-exclusion errors, source-time diagnostics and same-period sensor increments. Every regional `deployed` flag is false. Reproduce with `python -m pipeline.transfer_validation` after creating the local retained cell ledgers.
- The final refinement adds `recorded_robust_deviation = (value − median)/(1.4826 × MAD)`, `robust_deviation_definition` and `recorded_unusualness` to aggregate CSV. `recorded_mad_units` retains its prior unscaled meaning; no silent column redefinition occurs. The new score needs eight references and positive MAD. Labels use the documented rank/deviation gates. The public reference selector defaults to earlier years; exported `reference_policy` records the actual selection.
- `transfer-validation.json.final_refinement` preserves fixed-penalty regularized fits, year-block uncertainty and additional geographic/temporal splits. `matched_timing` contains one-to-one time-matched token statistics, including unmatched counts and daily-occupancy reconciliation. These scientific diagnostics remain in the repository, not in the explorer's navigation or statistical controls.
- Aggregate CSV adds `recorded_target_issues` (pipe-separated reason codes) and `reference_eligibility` (a quoted JSON array of `{period, eligible, reasons}` for every candidate year in the date filter). Codes distinguish `outside_date_filter`, `calendar_day_absent`, `sensor_configuration`, `platform_unavailable`, `historical_gap_advisory`, `nrt_records`, `record_gaps`, `target` and `later_year`. A target can have several reasons. `recorded_reference_n` counts eligible peers even if the target is unsupported; median/deviations remain blank then. `recorded_unusualness` now distinguishes an unsupported target from inadequate reference N. Existing units, thresholds and occupancy fields are unchanged.
